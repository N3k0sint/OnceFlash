Privacy Policy & Terms

OnceFlash is built on a strict Zero-Knowledge architecture. Privacy is not a feature we toggle it is mathematically enforced by end-to-end client-side cryptography.

1. Zero-Knowledge Cryptography

All encryption and decryption happens exclusively inside your web browser via window.crypto.subtle (Web Cryptography API) using AES-256-GCM with fresh 96-bit initialization vectors (IVs).

The decryption key is embedded in the URL hash fragment (e.g. #<id>:<key> or #room=<id>&key=<key>). In accordance with RFC 3986 §3.5, hash fragments are never transmitted across the network to our servers. As a result, our servers never see, possess, or store your encryption keys, plaintext notes, or chat contents.

When optional Password Protection is enabled (for notes or Flash Rooms), key un-wrapping is calculated client-side using PBKDF2 (100,000 iterations). Your passphrase is never transmitted across the network or stored on our infrastructure.

2. Ephemeral Storage & Irreversible Purge

All ciphertext payloads are stored strictly in volatile memory (RAM or ephemeral Redis cache) with an enforced time-to-live (TTL) expiration timer set by the creator.

  • Burn-on-Read: Notes configured for 1 view are deleted atomically immediately upon retrieval using atomic server-side evaluation to prevent double-read race conditions.
  • Automatic Expiration: When a secret reaches its view limit or countdown duration, it is permanently wiped and unrecoverable.
  • Dual Destruction: Both creators and recipients can trigger immediate destruction at any time.
  • No Disk Persistence or Backups: Ephemeral notes and chat buffers are never written to permanent disk storage, database tables, or backup archives.

3. Flash Rooms (Ephemeral Live Chat Sessions)

Flash Rooms provide temporary, end-to-end encrypted group chat sessions for up to 4 participants with a strict lifetime countdown (5 to 60 minutes).

  • End-to-End Encrypted Relay: Every chat message is individually encrypted with AES-256-GCM in the sender's browser before transmission. The server functions purely as a blind relay and holds only opaque ciphertext blobs in volatile RAM.
  • Anonymous Aliases: No real names, phone numbers, or user profiles are collected. Participants choose or are assigned a temporary Alias (nickname) that exists solely during the active session.
  • Tab-Scoped Session Isolation (Zero Cookie Tracking): Host administrative credentials and participant tokens are stored exclusively in sessionStorage, which is isolated strictly to your active browser tab. OnceFlash does not use authentication cookies or cross-tab local storage for room credentials, preventing cookie hijacking, CSRF attacks, and unintended administrative access across open tabs.
  • Voluntary Departure & Anti-Reentry Guarantee: When a user or host clicks "Leave Room", all local keys and session tokens are purged from browser memory immediately. To prevent session hijacking or unauthorized re-attachment, departed users cannot re-enter the session. If a host departs, the conversation continues for remaining participants until the timer expires, but host administrative controls cannot be reclaimed.
  • Immediate Room Destruction: Flash Rooms self-destruct upon expiration of the session timer or when explicitly triggered by the host. All messages, participant sequences, and room data are atomically and permanently purged from server memory.

4. Zero Tracking, Cookies, or Surveillance

OnceFlash is built on a radical privacy foundation and does not monitor, track, or profile you:

  • No User Accounts: You never register, log in, or provide personal identification.
  • No Tracking Cookies: We do not set persistent tracking cookies, marketing pixels, or analytics beacons.
  • Offline QR Generation: QR codes are generated 100% client-side in SVG format without making remote API requests to third-party barcode services.
  • No Third-Party Analytics: No Google Analytics, tracking pixels, or surveillance scripts are embedded.
  • No Referrer Leakage: Strict Referrer-Policy: no-referrer and security headers prevent secret link fragments from leaking to external destinations.
